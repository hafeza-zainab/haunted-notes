# Haunted Notes

A Vite + React + TypeScript study app. Turn typed notes, audio files, live speech and photos into fill-in-the-blank flashcards, then review them as ghosts that fade when you know the answer.

**Live app:** <URL>  
**Demo video:** <YouTube URL>

## What it does

- **Capture notes** by typing, live mic, uploading an audio file, or photographing printed text.
- **Cloze flashcards** generated by rules (no LLM). The blank is always the fixed `_____`, so its length never hints at the answer.
- **Spaced repetition** (SM-2 lite, `src/lib/srs.ts`). A correct answer banishes a ghost until it is due again; a wrong answer brings it back.
- **Ghosts** are inline SVG with five types (wisp, ghoul, banshee, phantom, poltergeist) chosen by weakness score. The demo shows all five on first load.
- **Quiz** with typo tolerance, hints, streaks and a round summary. Skipped and missed cards can be reviewed again.
- **Study insights** on the dashboard: current streak in days, cards reviewed today, accuracy over the last 7 days, the 3 weakest rooms, and a 7-day bar chart in plain SVG with a hidden table as the text alternative. The review history is capped at 500 events.
- **Export and import** all notes, cards and review history as a JSON file. Imports are validated as untrusted input, shown in a summary with a confirm dialog, and merged without duplicating cards or losing existing data.
- **Offline app shell** in production builds: a hand-written service worker and web app manifest cache the app shell only. The Audio tab shows whether the Whisper model is already cached in the browser.
- **Haunting atmosphere** and accessibility: dark palette with one accent glow, keyboard access, WCAG AA contrast targets, 44px tap targets and `prefers-reduced-motion` support.

## The Frankenstein stitch

| Piece | Tech (all free, runs in the browser) |
|---|---|
| Speech to text (audio files) | Whisper `whisper-tiny.en` via transformers.js, in a Web Worker |
| Live mic | Web Speech API |
| Photo to text | Tesseract.js with canvas preprocessing (greyscale, 2x upscale, mild contrast) |
| Notes to flashcards | Rule-based cloze generation (no LLM) |
| Review scheduling | SM-2 lite in a pure module (`src/lib/srs.ts`) |
| UI | React, Vite, TypeScript, Zustand, hand-built SVG ghosts |

No backend, no accounts, no paid services. Notes are stored only in your browser (localStorage). Export files stay on your device unless you move them yourself.

## Privacy, by input method

- **Audio files:** transcribed fully on-device (Whisper in a Web Worker).
- **Photos:** processed on-device by Tesseract.js, but its worker, WASM core and English language data are downloaded from a CDN on first use.
- **Live mic:** uses the browser's Web Speech API, which in some browsers sends audio to the browser vendor's speech service.

Network calls: the one-time Whisper model download (about 40 MB, then cached by the browser), the one-time Tesseract.js assets, and the browser's speech service for Live mic only. Nothing else leaves the browser. The service worker never caches the Whisper model or Tesseract assets.

## Run locally

```bash
cd haunted-notes
npm install
npm run dev
```

Click **Try demo**. Add `?dev=1` to the URL (for example `http://localhost:5173/?dev=1`) to show a +1 day time-travel button on the dashboard.

The service worker registers only in production builds. To try the offline shell:

```bash
npm run build
npm run preview
```

## Deploy

The repository is ready for free static hosting on Netlify. Nothing has been deployed yet.

1. In Netlify, choose "Import an existing project" and pick this GitHub repository.
2. Netlify reads `netlify.toml` at the repository root: it builds in `haunted-notes/` with `npm run build` and publishes `haunted-notes/dist`.
3. Deploy, then put the site URL in the **Live app** line at the top of this README.

`netlify.toml` also sets these headers: `sw.js` and `manifest.webmanifest` are sent with `Cache-Control: no-cache`, so a new build replaces the old service worker; hashed files under `assets/` are cached for a year as `immutable`. Unknown paths fall back to `index.html`; real files are always served first.

The app is served from the site root, which is where the service worker registers its scope. Serving it from a sub-path has not been tested.

## Known limits

- Offline behavior, installability and import safety in a real browser have not been verified yet (see the Kiro usage log).
- Audio transcription is English only (`whisper-tiny.en`).
- OCR works best with clear printed text.
